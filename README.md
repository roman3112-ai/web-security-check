# web-security-check (`websec`)

Учебный CLI-инструмент: маленький и **безопасный** (non-destructive) чекер
защитной HTTP-конфигурации сайта — security-заголовки, флаги кук и баннер,
который светит версию сервера. Он шлёт один обычный GET-запрос и смотрит на
ответ — никакого атакующего трафика, перебора паролей или сканирования
уязвимостей. Отвечает на один вопрос:

> *Настроен ли сайт так, как рекомендует OWASP?*

Поэтому его безопасно подключить в CI против собственного staging-сайта и
безопасно показать в качестве пет-проекта.

> ⚠️ Запускать только против сайтов, которыми вы владеете или на проверку
> которых у вас есть явное разрешение.

## Что проверяется

| Проверка | Критичность | Почему это важно |
|----------|-------------|-------------------|
| `Content-Security-Policy` | высокая | ограничивает, откуда грузятся скрипты/ресурсы |
| `Strict-Transport-Security` | высокая | заставляет браузер ходить по HTTPS при следующих визитах |
| `X-Content-Type-Options` | средняя | блокирует MIME-sniffing |
| `X-Frame-Options` | средняя | защита от clickjacking |
| `Referrer-Policy` | низкая | контролирует утечку referrer |
| `Permissions-Policy` | низкая | ограничивает браузерные API |
| Флаги кук | средняя | `Secure` + `HttpOnly` + `SameSite` у каждой куки |
| Server-баннер | низкая | ловит утечку номера версии сервера |

## Установка и запуск

```bash
pip install -r requirements.txt

python -m websec.cli https://example.com
# либо, если пакет установлен:
websec https://example.com --fail-on-high
```

Флаг `--fail-on-high` завершает процесс кодом `1`, если провалена хотя бы
одна проверка высокой критичности — так CI-джоба покраснеет при регрессии.

### Пример вывода

```
[ОШИБКА] высокий  header:content-security-policy — отсутствует
[OK    ] средний  header:x-content-type-options — есть
[ОШИБКА] средний  cookie:session — secure=False httponly=True samesite=False
...
Итог: 4/9 проверок пройдено
Хотя бы одна проверка высокой критичности провалена.
```

### Docker

```bash
docker build -t websec .
docker run --rm websec https://example.com
```

## Как это устроено

Все проверки — чистые функции над `httpx.Response`, поэтому тесты поднимают
два демо-приложения на FastAPI (одно уязвимое, одно защищённое) прямо через
ASGI-транспорт httpx — без сети. `tests/test_cli.py` дополнительно поднимает
эти же приложения на localhost через uvicorn и гоняет настоящий CLI целиком.

```
websec/
  models.py   # Finding, Severity
  checks.py   # проверки заголовков / кук / баннера + run_checks()
  report.py   # подсчёт очков и рендер текстового отчёта
  cli.py      # точка входа argparse
tests/
  demo_target.py  # уязвимое и защищённое FastAPI-приложения для тестов
  test_checks.py
  test_cli.py
```
